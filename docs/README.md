# Vaani documentation

Everything written about Vaani, grouped by what you want to do. The project overview is in the
[main README](../README.md); the running log of what was verified, changed and still open is [NOTES.md](../NOTES.md).

## Features: how each part works

| Document | What it covers |
|---|---|
| [APP_CASE_STUDIES.md](features/APP_CASE_STUDIES.md) | How Vaani operates other apps: Uber through accessibility, Pronto through screenshots and coordinate taps, where it stops for a yes, and the code checks that keep the AI in line |
| [HEALTHCARE_KT.md](features/HEALTHCARE_KT.md) | The doctor and emergency features end to end: red-flag detection, the ambulance API, hospital ranking, the background calls, booking on the line, number masking |
| [CARE.md](features/CARE.md) | The care feature's API, events and setup, for developers |
| [PERSONAL_ABILITIES.md](features/PERSONAL_ABILITIES.md) | The three demo users, their compiled abilities, and the shopping camera's sugar and salt warnings |
| [COMPILED_CODE.md](features/COMPILED_CODE.md) | Everything Vaani compiles (routines, recognisers, abilities), how it is tested and every sandbox layer |
| [LEARNING.md](features/LEARNING.md) | The learning loop, models, voice and memory in one overview |
| [MEKO_PROPOSAL.pdf](features/MEKO_PROPOSAL.pdf) | The two-page Meko feature proposal: why context matters, the design, every Meko use, privacy and live results |
| [MEKO_STATE.md](features/MEKO_STATE.md) | One memory per person, seven agents, where each fact was learnt, and the appointment that becomes a cab destination |
